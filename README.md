# Ёкси (Yoxy)

![Логотип Ёкси](static/logo.png)

Python-панель, которая создаёт Telegram **WEB-proxy** вместе с бесплатным
поддоменом dynv6, HTTPS и полноценным сайтом рецептов. Управление из браузера
на Android, Windows и других устройствах. В Python-части используются только
модули стандартной библиотеки.

## Установка одной командой

Выполните от root на VPS:

```bash
curl -fsSL https://raw.githubusercontent.com/riehnh/mtpoxy-panel/main/install.sh | bash -s -- --repo https://github.com/riehnh/mtpoxy-panel
```

Установщик выводит URL `https://IP:9443/manage`, пароль и SHA-256 отпечаток
сертификата. Первая установка включает сборку серверных компонентов и может
занять несколько минут. При нестандартной сети добавьте `--public-ip IPV4`.

Поддерживаются Ubuntu 22.04+ и Debian 12+, архитектура amd64/x86_64,
systemd и публичный IPv4. Откройте TCP 80, 443 и 9443 в firewall хостинга.
При активном UFW установщик добавляет эти разрешения.

Первичный вход по IP использует самоподписанный HTTPS-сертификат. Браузер
предупредит о нём. Сверьте отпечаток с выводом установщика и подтвердите
переход. После создания первого сайта панель доступна и по
`https://ИМЯ.dynv6.net/manage` с публичным сертификатом.

## Android · Ёкси 1.10

Готовый APK доступен на вашем VPS в панели **`/manage`** (также работает
**`/mange`**), только после входа. После установки из этой версии репозитория
кнопка **«Скачать Ёкси 1.10 · APK»** отдаёт файл
`/manage/download/android.apk`. Для уже установленной панели повторите команду
установки, чтобы получить обновлённый интерфейс и APK; настройки сохраняются.
Можно скачать файл напрямую из [репозитория](https://github.com/riehnh/mtpoxy-panel/raw/refs/heads/main/downloads/MTPoxy.apk).
Требуется Android 8.0 или новее.

- **Халява** — прежний «Впереть»: сбор выбранных публичных списков, проверка
  TCP-пинга, лучший доступный прокси, «Пихаем» и «Следующий».
- **Манул** — ручная загрузка, проверка и сортировка списка.
- **Жупень** — вращающаяся по часовой стрелке утка; подпись остаётся на месте.
  Открывает управление своим VPS: API dynv6, почта, создание WEB-proxy,
  состояние выпуска и подключение готовых прокси в Telegram.

При первом нажатии на утку введите **адрес и пароль панели**, выданные
установщиком, а не SSH-пароль root. Пример адреса: `203.0.113.12`
(автоматически используется HTTPS-порт 9443), `https://IP:9443/manage` или
`https://recipebook-xxxxxx.dynv6.net/manage`. Кнопка **«чё?»** объясняет установку
VPS и получение HTTP Token на dynv6. Для самоподписанного сертификата нужно
сверить SHA-256 с терминалом установщика; проверка имени сервера сохраняется.
Пароль хранится зашифрованным ключом Android Keystore. При следующих запусках
приложение само входит в панель. **«Изменить VPS»** открывает поля подключения;
новые данные заменяют сохранённые только после успешного входа.

Исходники Android находятся в `android/`, готовая сборка — `downloads/MTPoxy.apk`.
Сборка на Windows с JDK и Android SDK:

```powershell
./android/build.ps1 -Sdk 'C:\Users\YOU\AppData\Local\Android\Sdk'
```

Скрипт создаёт локальный ключ в `android/build/local.jks`, если его нет.
Храните свой ключ отдельно: он нужен для обновления ваших APK. Ключ готовой
поставки в репозиторий не включён, поэтому ваша самостоятельная сборка будет
иметь другую подпись. Результат: `android/build/MTProxy-Picker.apk`.

## Настройка WEB-proxy

1. Зарегистрируйтесь на https://dynv6.com и получите HTTP token в разделе Keys.
2. Откройте панель и войдите с паролем из терминала.
3. Сохраните токен dynv6 и email для ACME/HTTPS.
4. Нажмите **Создать WEB-proxy**. Имя `recipebook-xxxxxx.dynv6.net`
   генерируется автоматически. Также можно указать своё кулинарное имя.
5. Дождитесь DNS, запуска служб и HTTPS. Откройте готовую ссылку в Telegram.

Кнопку можно нажимать повторно: создаются новый кулинарный поддомен,
отдельный secret и новое подключение на том же VPS. Программной квоты на
число записей нет. Свободные порты выбираются автоматически, фактическое
количество ограничивают ресурсы VPS, DNS API и правила выпуска сертификатов.
Установки выполняются последовательно. Для неудачной установки кнопка
«Повторить» использует ранее созданное имя.

Нужен Telegram с поддержкой типа WEB. Ссылка `t.me/webproxy` содержит
`server` и `secret`. Эквивалент `tg://webproxy` используется кнопкой панели.

## Что создаётся

- Бесплатная DNS-зона через REST API dynv6. При повторе используется ранее
  созданная зона.
- Отдельный Telegram backend и WEB relay для каждого сайта, отдельные secret
  и ключ подписи. Процессы управляются systemd и запускаются после перезагрузки.
- Перед статусом «Готово» проверяется настоящий MTProto-ответ Telegram
  `resPQ`, а также HTTPS-сертификат и сайт.
- Сайт Recipe Book с фотографиями, поиском по названию и ингредиентам,
  фильтром кухни, быстрыми блюдами и полными рецептами в диалоге.
- Каталог из открытого API DummyJSON Recipes. Данные и инструкции на
  английском, интерфейс на русском. Обновление раз в сутки с сохранением
  последнего успешного каталога.
- Caddy получает и обновляет HTTPS-сертификаты.
- HAProxy маршрутизирует новый SNI в WEB-proxy. Другие подключения на 443
  передаются существующему TCP-сервису на `127.0.0.1:443`.

Если исходящие соединения к Telegram блокируются, раскройте в настройках
**Исходящий SOCKS5** и укажите адрес, порт и при необходимости логин/пароль.
В этом режиме используется Python-backend alexbers/mtprotoproxy, работающий
через SOCKS5 с серверами Telegram. На VPS с существующим локальным SOCKS5 в
x-ui установщик переносит его параметры в настройки панели автоматически.
Пароль SOCKS5 не возвращается браузеру. В прямом режиме используется
официальный Telegram MTProxy. Python-backend устанавливается из закреплённого
коммита, библиотеки cryptography и PySocks — пакетами Ubuntu/Debian.
Проверка обращается к пяти дата-центрам Telegram с повтором при тайм-ауте.
Если отвечает только часть, панель выводит предупреждение. Это может влиять
на подключение аккаунтов и медиа, требуется проверить или сменить выход VPS.

Установка не предполагает работающего веб-сервера на 80. Если VPS уже
обслуживает сайты через nginx/Caddy, освободите 80 или интегрируйте
конфигурацию вручную. Существующий сервис на 443 должен принимать IPv4
соединения через loopback. Конфигурации x-ui/Xray и его прокси не изменяются.
Прямая маршрутизация с NAT провайдера и IPv6 требуют отдельной интеграции.

## Приватность и доступ

API-токен хранится в `/var/lib/mtpoxy/settings.json` с правами 0600 и не
возвращается браузеру. Пароль хранится как PBKDF2-SHA256 с индивидуальной
солью. Есть защита POST-запросов по Origin и CSRF, ограничение попыток входа,
HttpOnly/SameSite cookies и срок сессии 8 часов. Панель управляет systemd и
firewall, поэтому служба работает от root. Доступ к ней даёт управление
создаваемыми прокси. Файлы конфигурации и пароль не входят в репозиторий.

Пароль первого входа можно повторно посмотреть от root:

```bash
cat /var/lib/mtpoxy/initial-password
```

Для смены пароля от root:

```bash
python3 /opt/mtpoxy/reset_password.py
```

Проверить состояние:

```bash
systemctl status mtpoxy-panel mtpoxy-caddy mtpoxy-router
journalctl -u mtpoxy-panel -n 100 --no-pager
```

Состояние задач сохраняется. После перезапуска прерванная установка получает
статус ошибки, её можно повторить кнопкой в панели. Если dynv6 не публикует
DNS, задача сохраняет имя и предлагает повтор без повторной регистрации.

Отключить перенаправление порта 443 и вернуть входящий трафик напрямую
предыдущему сервису:

```bash
systemctl disable --now mtpoxy-routing.service mtpoxy-router.service
```

Для резервной копии сохраните `/var/lib/mtpoxy`, `/etc/mtpoxy`,
`/etc/mtproxy` и папку сертификатов `/var/lib/mtpoxy/caddy`.

## API статистики

`GET /manage/api/stats` возвращает все прокси, а
`GET /manage/api/stats/ID` — один конкретный прокси. Требуется сессия панели
или отдельный ключ `Authorization: Bearer KEY` с правами **только чтения статистики**.
Ключ не позволяет читать настройки, ссылки/секреты прокси или создавать прокси.
Используйте адрес основной панели (IP:9443 или первый домен панели), HTTPS.

Для выдачи ключа войдите через `POST /manage/api/login`, передав JSON
`{"password":"ПАРОЛЬ_ПАНЕЛИ"}`. Сохраните cookie ответа и поле `csrf`.
Затем выполните `POST /manage/api/statskey` с JSON `{}`, тем же cookie,
заголовками `Origin: https://АДРЕС_ПАНЕЛИ` и `X-CSRF-Token: CSRF`.
Ответ: `{"key":"...","scope":"stats:read","revoked":false}`.
Ключ показывается только при выдаче, на сервере хранится его SHA-256.
Повторная выдача сразу отзывает прежний ключ; JSON `{"revoke":true}` на том же
endpoint отзывает ключ без создания нового. Для выдачи/отзыва Bearer недостаточно:
нужны парольная сессия панели и CSRF.

Пример получения ключа через Python 3 (пароль вводится без отображения):

```python
import getpass, http.cookiejar, json, urllib.request
base = input('HTTPS-адрес панели без /manage: ').strip().rstrip('/')
opener = urllib.request.build_opener(urllib.request.HTTPCookieProcessor(http.cookiejar.CookieJar()))
def post(path, data, csrf=''):
    req = urllib.request.Request(base + '/manage/api/' + path,
        data=json.dumps(data).encode(), headers={'Content-Type': 'application/json',
        'Origin': base, 'X-CSRF-Token': csrf})
    with opener.open(req, timeout=20) as response:
        return json.load(response)
login = post('login', {'password': getpass.getpass('Пароль панели: ')})
print(post('statskey', {}, login['csrf']))  # Сохраните ключ в надёжном месте.
post('logout', {}, login['csrf'])
```

Пример запроса (подставьте свой ключ и ID):

```bash
curl -fsS -H 'Authorization: Bearer ВАШ_КЛЮЧ' \
  https://ИМЯ.dynv6.net/manage/api/stats/1
```

Поля ответа:

| Поле в `sites[]` | Значение |
| --- | --- |
| `id`, `hostname`, `status` | Прокси и состояние выпуска |
| `available`, `sampled_at` | Доступны ли метрики; время замера Unix UTC |
| `active_sessions` | Живые сессии WEB relay, приблизительная активность клиентов |
| `active_connections` | Логические MTProto-соединения внутри сессий |
| `sessions_created_total`, `connections_opened_total` | Сессии/соединения с запуска relay |
| `bytes_up_total`, `bytes_down_total` | Байты к Telegram / от Telegram с запуска relay |
| `unique_ips_24h` | `null`: сбор уникальных IP не реализован |

Это не точное число людей или Telegram-аккаунтов. Считается полезная нагрузка
relay, без HTTPS-накладных расходов и посещений сайта рецептов.
Счётчики сбрасываются при перезапуске соответствующего relay
(`counter_scope: relay_process_lifetime`, `resets_on_relay_restart: true`).
Ответы кешируются на 5 секунд; `sampled_at` показывает фактическое время замера.
Если relay недоступен или прокси ещё не выпущен, `available: false`, счётчики
`null`, поле `error` объясняет причину. Один недоступный relay не обнуляет данные
других. Неизвестный ID даёт 404, неправильный ключ — 401.
История и уникальные IP не сохраняются. Для графиков опрашивайте API и храните
замеры в своей системе мониторинга, учитывая сброс счётчиков.

Уже установленную панель обновите повтором команды установки; APK менять
для доступа к API не требуется. Локальные `/metrics` остаются на loopback.

## Название и оформление

Проект называется **Ёкси (Yoxy)**. Логотип — утверждённая жёлтая утка с хохолком и оранжевым клювом, без надписей и предметов. Android 1.7 сохраняет совместимость обновления с MTPoxy: package ID, подпись и сохранённые подключения прежние. Технические пути `/opt/mtpoxy`, API `/manage` и имя репозитория сохранены.

В панели отображается название **MTPoxyЁкси**. Самолётик в клюве использует исходный контур Telegram с равномерным масштабированием без искажения пропорций.

## Интерфейс 1.8

В панели три раздела: «Прокси», «Настройки», «Приложение». APK доступен только после авторизации: и раздел скачивания, и сам endpoint требуют входа. ## Android 1.9: Flat UI

Утверждённая утка используется в панели, сайте рецептов, Android-иконке и вращающейся кнопке. Android получил плоские прямоугольные блоки: янтарный VPS, коралловый автопоиск, голубой ручной выбор и графитовые формы. Файл `static/logo.png` — исходный PNG с прозрачностью.

## Android 1.10: список в «Халяве»

При входе пустой список автоматически загружается и проверяется. Если список уже
есть, показываются сохранённые результаты TCP-пинга и время замера, без повторной
загрузки. Результаты сохраняются и между запусками приложения.

- **Обновить список** — загрузить выбранные источники и проверить новый список.
- **Проверить** — проверить уже сохранённый список, не скачивая источники.
- **Давай!** — открыть прежнее окно «Пихаем» / «Следующий», начиная с лучшего
  доступного результата. Перед показом каждого варианта доступность проверяется заново.
- **Хочу!** у любой строки — открыть то же окно для выбранного прокси и заново
  проверить его пинг. Для не ответившего прокси «Пихаем» отключена; можно перейти
  к следующему варианту или вернуться в список.

Список отсортирован по пингу после общей проверки, недоступные адреса идут в конце.
Для больших списков кнопка «Показать ещё» добавляет по 60 строк. Смена источников
очищает сохранённый список и результаты. Если все источники недоступны при обновлении,
предыдущий список сохраняется.

Ускорение: источники загружаются параллельно, опрос выполняется в 32 потока,
одинаковый host:port измеряется один раз за проход, DNS разрешается ограниченным
пулом с кешем на проход. Общий бюджет DNS + TCP — 1,5 секунды на адрес;
проверка выбранного варианта — 2 секунды. Короткий таймаут может отсеять медленное
соединение: «Хочу!» позволяет проверить его отдельно. Это TCP-пинг, а не проверка
авторизации MTProto или точное измерение качества Telegram.

Локальные JVM-проверки выбора и сетевых ограничений: `android/tests/FreeFlowCheck.java`
(компилируется с `android.jar` и классами приложения). Интерфейс на устройстве
нуждается в отдельной проверке.

## Android 1.11: оценки пинга

«Найти!» — зелёная кнопка выбора лучшего прокси. При обновлении списка (включая
первую загрузку) до конца загрузки и проверки на экране остаются только
анимированные кубики. При ошибке возвращаются список и сообщение; если список
был пуст, бесконечного повторного обновления нет.

| TCP-пинг | Оценка | Цвет |
| --- | --- | --- |
| 0–99 мс | Лучший | Зелёный |
| 100–249 мс | Норм | Светло-зелёный |
| 250–499 мс | Сомнительно | Жёлтый |
| 500–999 мс | Кал | Оранжевый |
| 1000 мс и выше | Бяда | Красно-оранжевый |
| Не ответил | Помер | Красный |

До измерения — нейтральная надпись «Не проверен». Оценки применяются в списках
«Халявы», ручного выбора и в окне подключения. Это условная оценка TCP-пинга,
а не гарантия работы Telegram. «Лучший» — категория задержки, «Найти!» выбирает
минимальный фактический пинг среди доступных адресов.

## Android 1.12: прогресс и отмена

Зелёная кнопка выбора лучшего прокси теперь называется «Давай!».
Для «Обновить список» и «Проверить» используется одна компактная панель:
кубики, текущий этап, счётчик выполненного и кнопка «Стопэ».
Во время загрузки показано число обработанных источников, во время TCP-проверки —
число адресов и процент. Системная кнопка «Назад» на этой панели также отменяет операцию.

«Стопэ» возвращает к прежнему списку и его результатам. Новый список и пинги
применяются только после полного завершения проверки. Сетевые задачи отменяются,
загрузочные соединения закрываются в фоне; запоздалые ответы отменённого или
завершённого запуска игнорируются. После отмены можно сразу запустить новую проверку.
JVM-тест отмены: `android/tests/CancellationCheck.java`.

## Android 1.13: свой список и обновления

Главная: «MTPoxyЁкси», «Это вам не это», «Тележенька ты где?» и «Надо только
облизнуть». Центральный блок — «Халява», ниже — свой VPS и «Манул». Внизу
«Хелпинг» с инструкцией и «Факинг» с автором riehnh и ссылкой на этот репозиторий.
В панели своего VPS и в «Мануле» есть возврат «На главный экран».

«Манул» — отдельная личная коллекция. Можно вставить одну или несколько ссылок
`tg://proxy`, `https://t.me/proxy`, `tg://webproxy` или `https://t.me/webproxy`,
импортировать сохранённый список из «Халявы» либо получить выбранные источники.
Импорты дополняют коллекцию без дубликатов; пользовательские записи не заменяются.
Можно проверить пинг, подключить или удалить запись. Данные сохраняются на устройстве.
Для WEB-прокси проверяется только TCP-порт 443.

При каждом запуске проверяется `updates/latest.json` из этого GitHub-репозитория.
Сравнение идёт по числовому Android `versionCode`, а не по текстовой версии.
При наличии новой версии предлагается открыть фиксированный адрес APK в GitHub;
скачивание и установка требуют действий пользователя. Нет автоматической установки
и передачи паролей. Если GitHub недоступен, проверка молча пропускается и не блокирует
приложение. Первую версию с этой функцией (1.13) нужно установить вручную.

При выпуске обновляйте вместе `android/AndroidManifest.xml`, `updates/latest.json`
и `downloads/MTPoxy.apk`. Подписывайте прежним ключом, иначе Android не сможет
обновить установленное приложение с сохранением данных.

## Android 1.14: анимация и работа со списками

В шапке «MTPoxyЁкси» без @. Кнопки «На главный экран» используют общий компонент
во всех разделах. «Жупень» — жёлтая плитка с утверждённой уткой. На «Халяве»
встроен переданный автором ролик `android/res/raw/free_animation.mp4`: локальный
зацикленный MP4 без звука, останавливается при уходе с экрана. Видео не требует сети.

В «Мануле» панель инструментов остаётся над прокручиваемым списком. Добавлены
поиск по адресу/порту/типу, фильтры «Все», «Живые», «Мёртвые», «Не проверены»,
сортировка по пингу/адресу и счётчики. «Добавить / импорт» объединяет вставку ссылок,
импорт из «Халявы», получение источников и копирование всей коллекции. В меню строки
можно скопировать ссылку или удалить запись. Проверка и импорт показывают прогресс.

«Удалить мёртвые» удаляет только записи с результатом последней проверки -1.
Непроверенные (-2) и ответившие адреса сохраняются. Последнее одиночное или массовое
удаление можно отменить кнопкой «Отменить удаление» до закрытия раздела. Оценка TCP
не гарантирует работоспособность Telegram и может зависеть от текущей сети.
